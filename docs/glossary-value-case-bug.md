## Отменённая ветка: case-sensitive матчинг (`cs`) — откатана 2026-07-10

Была попытка (коммит `d82b016`) точечно матчить часть терминов с учётом
регистра: значение-объект получал флаг `cs: true`, а регистр ключа служил
маркером режима. Цель — 7 терминов, у которых строчная форма это обычная проза
с другим смыслом: `Attack` (глагол `attack`, 1269 вхождений), `Force`,
`Sway`, `Insight`, `Stab`, `Hack`, `Upswing`.

**Почему откатано.** Регистр оказался дырявым прокси и течёт в обе стороны:
глагол с заглавной в начале предложения («Attack the enemy…») ловился как стат,
а строчные упоминания стата («your attack», ~40 шт.) терялись. Глагол и стат
живут в одних и тех же боевых файлах, так что и «по файлам» не разделить.
По данным `.txt/.tsv` заглавный стат-термин вообще не встречается внутри прозы —
только как самостоятельная UI-подпись; прозаические/глагольные употребления
строчные. Механизм добавлял заметную сложность (два регекса, guard на заглавную,
колонка `cs`, ключ-как-маркер) ради 7 неоднозначных общеупотребимых слов —
не окупалось.

**Что сделано (2026-07-10).** cs-механизм убран целиком — код (`load.ts`,
`match.ts`, `candidates.ts`, `sheet.ts`) и `data/glossary.json5` откатаны к
пред-cs состоянию (`fbe12f0`, файл байт-в-байт). 7 терминов ОСТАВЛЕНЫ в
глоссарии обычными case-insensitive строками с их оригинальными переводами
(Attack→атака, Force→мощь, Sway→смятение, Insight→познания, Stab→колющий,
Hack→рубящий, Upswing→восходящий) — решили сохранить термины и готовые переводы,
убрав лишь cs-механику. **Готовые переводы (TM) НЕ трогали** — `rebuild-tm`
не запускался, оверлей остаётся как есть. По сути это обычный откат коммита
`d82b016`, только регенерированные им TM-файлы оставлены на месте.

Базовый фикс регистра значений (рекейс + `sourceText`, см. ниже) сохранён.

**Осталось (от базового фикса):** платная ретрансляция инвалидированных

## Симптом

Термины глоссария в переводе получают неправильный регистр: нарицательные
существительные выходят с заглавной буквы посреди русского предложения.

> «восстанови свою **Ци** в **Секте**» ← должно быть «...ци... в секте»

При этом настоящие имена собственные (Инь, Ян, Дао, Будда, Даньтянь) выглядят
правильно — поэтому поведение кажется «кривым»: часть терминов капитализируется
верно, часть нет.

## Корневая причина

Все **221 из 221** RU-значений в [`data/glossary.json5`](../data/glossary.json5)
записаны **с заглавной буквы**, включая нарицательные:

```
Qi           → Ци
Martial Art  → Боевая техника
Deviation    → Отклонение
Inner Breath → Внутреннее дыхание
```

Значений со строчной буквы — ноль. Мид-предложения такие термины должны быть со
строчной; заглавная нужна только именам собственным.

В [`src/engine/yandex.ts`](../src/engine/yandex.ts) (`glossaryPairsForTexts`,
~строка 165) значение уходит в пару **дословно** (`translatedText: ru`) с
`exact: false`. Флаг `exact:false` заставляет нейроглоссарий склонять термин по
грамматике, но **ведущую заглавную букву тащит в вывод**. Ни `pipeline.ts`, ни
матчер регистр значения нигде не нормализуют.

Проверка данных:

```bash
node -e '
const JSON5=require("json5");const fs=require("fs");
const p=JSON5.parse(fs.readFileSync("data/glossary.json5","utf8"));
let cap=0,low=0;
for(const [k,v] of Object.entries(p)){
  if(k.startsWith("_"))continue;
  const ru=typeof v==="string"?v:v.ru; if(!ru)continue;
  const f=ru[0];
  if(f!==f.toLowerCase())cap++; else if(f!==f.toUpperCase())low++;
}
console.log("UPPERCASE-initial:",cap,"lowercase-initial:",low);
'
# => UPPERCASE-initial: 221 lowercase-initial: 0
```

## Побочный, более мелкий момент

В [`src/glossary/match.ts`](../src/glossary/match.ts) (~строка 65) исходный
термин лауеркейзится (`m[0].toLowerCase()`), и этот же строчный вид становится
`sourceText` пары ([`yandex.ts`](../src/engine/yandex.ts) ~строка 176), тогда как
в тексте запроса регистр сохраняется. Пример:

```
REQUEST TEXT:  "True Qi restored. Your Qi grows in the Sect."
GLOSSARY PAIR: {"sourceText":"true qi", ...}   // строчные против "True Qi" в тексте
```

Латентно: сработает как баг, только если матчинг Яндекса чувствителен к регистру
букв (документация про это молчит; feed-механизм для точек намекает, что матчинг
довольно буквальный). Не корневая причина, но стоит поправить заодно.

## Варианты фикса

1. **Данные (основной).** Привести значения к «серединному» регистру: строчная
   буква для нарицательных, заглавная только для имён собственных
   (Инь, Ян, Дао/Тао, Будда, Даньтянь, Гу, названия сект/мест и т.п.).
   - Плюс: бьёт прямо в причину, прозрачно.
   - Минус: термин в начале предложения может выйти со строчной (Яндекс, правда,
     часто сам капитализирует начало предложения).
   - После правки нужен рефреш TM (значения меняются → сигнатура глоссария
     инвалидирует затронутые юниты; глобальный `GLOSSARY_VERSION` бампать не надо,
     хватит per-text srcHash).

2. **Код (контекстный регистр).** В `glossaryPairsForTexts` приводить ведущую
   букву значения к регистру найденной словоформы в тексте (заодно чинит и
   `sourceText` из побочного пункта — для этого надо сохранить оригинальный
   `m[0]` в матче, а не лауеркейзить).
   - Ограничение: Яндекс применяет **один глоссарий на батч**, поэтому «в начале
     предложения — заглавная, в середине — строчная» для одного и того же термина
     в одном батче не выразить. Придётся выбирать одну форму на пару.

Рекомендация: **вариант 1** как основной, при желании + фикс `sourceText`.
