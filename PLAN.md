## Решения (зафиксированы)

- **Источник:** `Language_EN` (английский). **Цель:** русский (`ru`).
- **Эталон смысла:** `Language_CN` (китайский оригинал) — для дизамбигуации и будущей семантической валидации (EN сам машинный с CN).
- **Движок перевода:** Yandex Translate API.
- **Вывод:** перезапись на месте в `Language_EN` (через junction в корне репо) — обязателен авто-бэкап + атомарная запись + round-trip перед записью.
- **Процесс:** строго поэтапно; коммиты делает только пользователь после ревью.

## Ключевые факты о данных (из разведки)

- 3 формата: парные `.txt` (225 файлов), `.tsv` (`EncyclopediaAssets`), вложенный `.json` (`CommonTip`).
- `.txt`: UTF-8 без BOM, **LF**, формат «нечётная строка = ключ / чётная = значение».
- Переносы внутри значения обычно кодируются `<NL>`; ключи могут содержать точки, пробелы и хвостовой пробел.
- Разметка к сохранению дословно: `{0}/{1}/{2}`, `<color=#..>…</color>`, `<align=..>`, `<line-height=..>`, `<NL>`, `<Character key=.. str=../>`.
- Языки имеют общий набор ключей → склейка EN↔CN **по ключу**, не по номеру строки.
- Всего ~**158 104** единицы перевода в `.txt` (без tsv/json).
- **2 файла-исключения** с реальными многострочными значениями: `CricketPolymorphEvent`, `ImplementedDlc` — в карантине.
